title: Applications

Use this guide to share a deployed app with your team. You need an authenticated
CLI session and app-admin or organization-administrator permissions. Start with
[your first deployment](/getting-started/installation) if the app is not running yet.

## Check the app

Run these commands from the app project, with `PLATFORM_URL` set to your installation:

```sh
widefleet whoami
widefleet apps
widefleet access
```

`apps` lists the apps you can manage, including their IDs. `access` reads the app
named in `wrangler.jsonc`; it does not change who can open the app.

## Choose who can open it

Company sign-in is always required. App roles grant access to a person or SSO group.
For a group that should only use the app, obtain its stable ID from your identity provider:

```sh
widefleet roles grant --group GROUP_ID --role user
widefleet roles show
widefleet access
```

Use `developer` to allow deployments, logs, database migrations and Workflow management,
or `admin` to also manage permissions, catalog visibility and deletion. Exactly one
person or group owns the app. Existing and future previews inherit these assignments.
Role changes save management permissions immediately; `access` shows whether the gateway
has activated the app usage rules.

To explicitly allow every authenticated company user:

```sh
widefleet access set --all-authenticated true
```

To require an assigned role again:

```sh
widefleet access set --all-authenticated false
```

These commands wait for gateway activation by default. In management, use **Access →
App roles** for role assignments and shared administration, and **Access → App usage**
for the all-authenticated switch and activation status. All app roles include usage;
workspace administration alone does not grant it. Business permissions inside the
app remain the app author's responsibility.

## Make the app discoverable

Replace `APP_UUID` with the app ID shown by `widefleet apps`:

```sh
widefleet catalog publish APP_UUID
widefleet catalog list
```

Only original apps with an active deployment can be listed; previews cannot. Colleagues can
find it in **App catalog** and follow its launch URL. Listing an app does not grant
management access or bypass its SSO and group rules. Use
`widefleet catalog unpublish APP_UUID` to withdraw the listing without deleting the app.

## Verify access

Open the launch URL with an intended user's account. Check that an account outside
the allowed groups is denied. After changing directory memberships, sign in again:
existing SSO sessions can retain earlier group claims.

If access activation fails, inspect `widefleet access` and the reported error. The
last installed rules can remain active; a saved change is not proof of enforcement.
After the operator resolves the cause, save the intended rules again and verify.
