For installation and your first deployment, start with [CLI setup](/getting-started/installation).
Use `widefleet --version` and `widefleet --help` to check the installed release.
Each command also accepts `--help`; newer commands require matching platform components.

## Authentication and target

| Setting or command                                  | Meaning                                                                                                   |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `PLATFORM_URL` / `--url URL`                        | Explicit management origin; overrides saved and managed configuration.                                    |
| `widefleet login`                                   | Browser device login; requests `platform:read platform:write` by default.                                 |
| `widefleet login --email EMAIL` / `--domain DOMAIN` | Discover the installation using a work email or company domain, then log in.                              |
| `widefleet config show`                             | Inspect the selected platform URL, its source and configuration paths.                                    |
| `widefleet config set-url URL` / `unset-url`        | Save or clear the platform URL without changing credentials.                                              |
| `PLATFORM_CONFIG_FILE` / `--config-file PATH`       | Use one explicit configuration file instead of the user and managed defaults.                             |
| `widefleet whoami`                                  | Inspect the authenticated user.                                                                           |
| `widefleet logout`                                  | Revoke the stored refresh token and remove the saved session.                                             |
| `PLATFORM_SESSION_FILE` / `--session-file PATH`     | Explicit, unencrypted session file for headless Unix use instead of the OS credential store.              |
| `PLATFORM_ACCESS_TOKEN`                             | Externally supplied token; overrides saved credentials for API commands and does not renew automatically. |

Keep session files outside projects and shared artifacts. The CLI restricts file
permissions and renews saved sessions automatically. See [headless login](/getting-started/installation#headless-login).

Login reuses configured or saved URLs and otherwise asks for a work email or
company domain. After a successful login it saves the URL. See
[CLI configuration](/reference/cli-configuration) for precedence, native file paths
and discovery behavior, or [company setup](/self-hosting/company-setup) to configure employees' agents.

## App commands

`APP_UUID`, `DEPLOYMENT_UUID` and `ARTIFACT_UUID` below are placeholders. Find app
IDs with `widefleet apps` and deployment IDs and artifact IDs with `widefleet history APP_UUID`.

| Command                                          | Purpose                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------- |
| `widefleet init DIRECTORY [--template TEMPLATE]` | Create an independent app; defaults to SvelteKit. No login required. |
| `widefleet apps`                                 | List apps you can manage.                                            |
| `widefleet deploy [APP_UUID]`                    | Build and deploy; normally selects the configured app name.          |
| `widefleet preview --name review`                | Build and deploy an isolated preview of an existing app.             |
| `widefleet history APP_UUID`                     | Read deployment history as JSON.                                     |
| `widefleet events APP_UUID DEPLOYMENT_UUID`      | Read deployment events.                                              |
| `widefleet rollback APP_UUID ARTIFACT_UUID`      | Activate a retained code artifact.                                   |
| `widefleet logs --level error --since 1h`        | Query app runtime errors; `--follow` keeps polling.                  |
| `widefleet migrations list DB` / `apply DB`      | Inspect or explicitly apply SQL migrations to a deployed D1 binding. |
| `widefleet access`                               | Inspect app usage rules; `set` changes the group list.               |
| `widefleet network`                              | Inspect external destinations; `allow` and `deny` change grants.     |
| `widefleet connector bindings`                   | Inspect IT-managed connector bindings.                               |
| `widefleet connector catalog`                    | Browse connector names and available entrypoints.                    |
| `widefleet connections`                          | Inspect desired and active connectors and deployed app resources.    |
| `widefleet catalog list`                         | List published app launch URLs.                                      |
| `widefleet delete APP_UUID --yes`                | Request removal of an app and all its previews.                      |

The target is the selected platform URL plus `name` in `wrangler.jsonc`. The first deploy creates that app; subsequent deploys update it after checking the user's app permissions. A changed name selects a different app. The server assigns the host, and existing apps keep their host and data.
Logs, access, network, connections and migrations also use project context; history, events and
rollback require IDs. Each command's help lists its selection options.

See [connector discovery and app connections](/guides/connectors#find-connectors-and-inspect-your-app)
for permissions, activation states and app selection.

## Create a project

Use CLI 0.3.3 or newer for the TanStack Start template and the Node.js 22.18
minimum. Check the installed version with `widefleet --version`.

```sh
widefleet init my-app
widefleet init my-react-app --template tanstack-start
```

`--template` accepts `sveltekit` and `tanstack-start`. Omitting the option is
equivalent to `--template sveltekit`. The CLI includes both templates, so project
creation needs no platform login or template download. Dependency installation
still requires the package registry or a populated local package cache.

`DIRECTORY` must not exist. The CLI derives the app name in `wrangler.jsonc` from
the directory name; review it before deploying. An unknown template exits with an
error and does not create a project. If the installed CLI rejects `--template`,
check `widefleet --version` and upgrade to CLI 0.3.3 or newer.

Inside either project, run `pnpm install --frozen-lockfile`, `pnpm check`, then
`pnpm dev`. Follow [app development](/guides/app-development) for identity,
bindings and the next deployment.

## Deployment flags and output

These flags apply to both `deploy` and `preview`:

| Flag            | Behavior                                                                      |
| --------------- | ----------------------------------------------------------------------------- |
| `--config PATH` | Read another Wrangler configuration; project paths are relative to that file. |
| `--skip-build`  | Upload the existing build instead of running the app build.                   |
| `--no-wait`     | Return the queued deployment; activation follows asynchronously.              |
| `--json`        | Print one result on stdout; build output and progress go to stderr.           |

After activation, the command prints `Deployment succeeded` and the app URL. For automation, use `widefleet deploy --json`: stdout contains one JSON object with the final deployment fields and `url`, while build output and progress go to stderr. The `id` field identifies the deployment and `appId` identifies the app. Existing scripts that parsed the default JSON output must add `--json`. With `--no-wait --json`, the result describes the queued deployment. Uploading with `--no-wait` requires only `platform:write`; waiting for deployment events and history also requires `platform:read`. Failures exit nonzero and leave stdout empty. Update the management server together with the CLI so it can provide the complete URL, including its configured HTTPS port.

Each command's help documents its output options.

For a complete task, follow [sharing an app](/guides/applications) or
[deployments and recovery](/guides/deployments).

See [CLI authentication](/reference/authentication) for credential stores and headless sessions.
